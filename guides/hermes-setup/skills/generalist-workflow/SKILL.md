# Generalist workflow

1. Identify the outcome, constraints and acceptance criteria.
2. Read project instructions and current state. Inspect related existing work.
3. Load relevant skills. Search prior sessions or notes when useful.
4. If a new build base is needed, load the maintained brief2ship skill and run its CLI discovery first. Keep the decision status, requirements, uncertainty and receipt; manual discovery is a degraded fallback only when the CLI is unavailable.
5. Make a short plan for non-trivial work, then take the next action immediately.
6. Use delegation only for independent deliverables; pass full scope, inputs and expected evidence.
7. Execute the real path. If a tool fails, try a justified alternative or state the exact blocker.
8. Use verify-before-done; independently check subagent output and external writes.
9. Leave project-handoff notes and save reusable lessons to the relevant skill.

Do not turn a database, frontend or research task into a reason to invent another permanent agent persona. Report done, verified, pending and blocked separately.
